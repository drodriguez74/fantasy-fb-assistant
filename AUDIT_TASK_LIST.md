# Audit Task List

Generated by an end-to-end audit (spec-vs-implementation gap analysis + test suite verification) against the FastAPI backend / React frontend. Findings are evidence-based: each item below was reproduced (failing test, 500 response, broken `tsc -b`, etc.), not inferred from reading code alone.

Baseline commit before this audit: `8ae3635` (repo had no git history prior to this).

## P0 — Critical (broken builds, mocked endpoints presented as live, safety)

- [x] **`backend/app/services/sleeper_service.py`: unhandled `httpx.HTTPStatusError`.** Every method calls `response.raise_for_status()` but only catches `httpx.RequestError` (a sibling exception class, not a parent of `HTTPStatusError`). Sleeper's `/stats/nfl/regular/{season}` endpoint 404s, so `get_player_stats()` throws unhandled. Fixed in `sleeper_service.py`, and the identical pattern was also found and fixed in `espn_service.py` and `yahoo_service.py` (14 more sites).
- [x] **`sleeper_service`/`espn_service`/`yahoo_service`: shared `httpx.AsyncClient()` created once in `__init__` breaks across event loops** ("Event loop is closed"). The client's connection pool binds to whichever loop is running on first use; a later call from a different loop (e.g. successive `TestClient` requests, each with its own loop) fails. This — not just the `HTTPStatusError` swallowing above — was the actual root cause of the `test_get_player_by_id` 500. Fixed by making `.client` a lazy property that recreates the `AsyncClient` whenever the running loop changes.
- [x] **`GET /players/{player_id}` response has no `id` field**, only `sleeper_id`, while `GET /players/` returns list items keyed by `id`. Same logical resource, inconsistent contract between list and detail. Added a matching `id` field to the detail response.
- [x] **`POST /api/v1/auth/login` is a hardcoded demo stub.** It ignored the database and only accepted `demo@test.com` / `Password123` — a fabricated identity matching no seeded user (the real demo accounts, `admin@fantasyfootball.com`/`admin123` and `test@example.com`/`password123`, live in `init_db.py`) — so real registered users (via `/auth/register`, which *does* write to the DB) could never log in. `UserService.authenticate_user()` already existed, fully implemented (password verification, lockout after 5 attempts), but was never called from anywhere. Rewired `/login` to use it and issue real JWTs.
- [x] **`GET /api/v1/auth/me` ignored authentication entirely.** No `Depends(get_current_user)`, no token check — always returned a hardcoded demo user object regardless of who (or whether anyone) was logged in. Now uses `Depends(get_current_active_user)` and returns the real authenticated user.
- [x] **`tests/test_auth.py` permanently overrode the shared `app`'s `get_db` at module-import time with no teardown.** Once its tests finished (and dropped their tables), *every other test file* that ran afterward in the same pytest session was silently redirected to test_auth's now-empty SQLite DB — the actual root cause of `test_search_players` intermittently 500ing only when the full suite ran. Moved the override into an `autouse` fixture with proper teardown.
- [x] **Frontend production build is broken (`npm run build` fails).** `tsc -b` errors: `LeagueDetailPage.tsx` references `RosterAnalysis.team_name`, `.grade`, `.strengths_weaknesses`, `.composition`, `.composition.players` — none of which exist on the `RosterAnalysis` type (`src/types/index.ts`). Also `PostDraftAnalysisPage.tsx:55` has an unused `user` var (`TS6133`).

## P1 — High (incomplete loops, stale docs/tests, spec discrepancies)

- [x] **Backend test suite doesn't run as documented.** `pytest` (bare, as documented in README/DEVELOPMENT.md) fails immediately: `ModuleNotFoundError: No module named 'app'`. Only `python -m pytest` works, because that form prepends cwd to `sys.path` while bare `pytest` does not. No `pytest.ini`/`pyproject.toml` configures `pythonpath`.
- [x] **`backend/tests/test_auth.py` targets a route that doesn't exist.** Tests POST to `/api/v1/auth/token`; the actual registered route is `/api/v1/auth/login` (this matches what the frontend's `api.ts` actually calls, so the frontend is correct and the tests/README/API_GUIDE are stale). Also `test_user_registration`/`test_duplicate_registration` use a password (`testpassword123`) that fails `UserCreate`'s validator (needs an uppercase letter), so registration 422s before the intended assertion is ever reached.
- [x] **`backend/tests/test_players.py::test_search_players` calls a nonexistent contract.** It GETs `/players/search?query=allen` expecting a `results` key; the real, registered route is `/players/search/{player_name}` (path param, not query string) and returns `matches`, not `results`. Since the frontend never actually calls this endpoint (`PlayersPage.tsx` filters the already-fetched list client-side), there's no real consumer to reconcile against — updated the test to match the real endpoint contract rather than inventing a second one.
- [ ] **Yahoo league connect (`leagues.py` "Connect to Yahoo Fantasy Sports (demo mode)") is a stub.** Not touched in this pass — flagging for follow-up since it affects the League integration feature described in the README as functional.
- [ ] **`draft_assistant_service.py` Sleeper/ESPN/Yahoo "get draft state" methods return mock data** ("demo mode with mock data"), despite `LIVE_DRAFT_TEST.md` documenting this as a real, testable feature. Not touched in this pass — needs product decision on whether live draft state should hit real platform APIs before further work.
- [ ] **`content_generation_service.py`: unimplemented content types** return `{"error": "Content generation not implemented for: {content_type}"}` silently rather than surfacing a 4xx. Not touched in this pass.
